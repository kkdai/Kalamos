# Kalamos Web 版實作計畫：以自管資料庫對齊桌面版

Created: 2026-11-23
Updated: 2026-11-23

## Goal

在本機瀏覽器提供 Kalamos 的完整寫作流程：匯入本機 Markdown 與附件、單欄即時預覽、編輯及儲存至自管 PostgreSQL，再從工作區重開或匯出。首版以桌面版功能為基準，公式、圖表、本機圖片預覽及轉檔不能因分段實作而被視為後續功能。

## Context

- [Web PRD](../../PRD.md) 定義 WEB-01 至 WEB-06；[ADR 0002](../decisions/0002-self-managed-database.md) 確認自管資料庫和本機開發。此計畫開始前，[Compose](../../compose.yaml) 只啟動 PostgreSQL 17，沒有 Web、API 或資料表。
- 功能盤點以[桌面版 README](../../../README.zh-TW.md)、[桌面版 PRD](../../../docs/PRD.md)、[桌面入口](../../../src/main.ts)與測試為準。桌面版的檔案、原生選單和 Tauri 呼叫集中在入口與 [IPC](../../../src/ipc.ts)；[現有 Playwright](../../../playwright.config.ts) 走記憶體模擬，不是 Web 儲存驗收。
- 實作範圍主要放在 `web/`。只在確有共享需求時調整根目錄工具設定或 `src/`；維持桌面版的 API、行為與發布流程。

## Non-Goals

- 不配置公開網域、不修改官網或部署流程、不開放遠端存取，不加入帳號、多人協作或雲端同步。
- PostgreSQL 是工作區的權威來源。匯入不覆寫原檔，Web 不直接讀取或監聽任意本機路徑；對應工作用瀏覽器選檔、附件匯入與資料庫更新完成。

## Architecture

- **前端**：新增 `web/` 專用入口，沿用 TypeScript、Vite、CodeMirror 與現有樣式。先共用[編輯器核心](../../../src/editor/index.ts)，將[圖片](../../../src/editor/images.ts)和[外部連結](../../../src/editor/live-preview.ts)的宿主行為交由 Web 或桌面各自處理。不把 Tauri 入口或模擬 IPC 放進 Web 產物。
- **本機 API**：建議用 Node.js 22（符合[現行 CI](../../../.github/workflows/ci.yml)）與 TypeScript，前端使用同源 `/api`，開發時由 Vite 代理。最終本機 Compose 由應用程式服務提供 Web 頁面和 API，對主機只綁定回送位址；Web 建置產物不含 DB 連線資訊。拒絕未授權來源的寫入請求。
- **資料**：以版本化 SQL 遷移建立工作區階層、文件、附件與設定。文件用穩定 ID 識別，路徑供導覽與相對連結使用；初版建議附件內容也存 PostgreSQL，檔案大小與支援類型列入驗收。匯入及關聯寫入交易完成後才回報成功。文件儲存攜帶讀取時的版本，避免兩個分頁靜默互相覆蓋。
- **匯出**：重用[匯出 HTML](../../../src/export/html.ts)與[圖表渲染](../../../src/export/diagrams.ts)；PDF 與 Pandoc 在本機服務的受限環境處理，不由文件內容指定命令。瀏覽器只傳輸選取或目前編輯的內容，並收取下載結果。

## Plan

**本機實作與驗收完成。** 39 項 Web 瀏覽器案例（含 1 項獨立圖床替身）、8 項 API、4 項轉檔及資料還原已驗證。結果與人工檢查移交至[功能對照表](../desktop-parity.md)，交付見[草稿 PR #114](https://github.com/kkdai/Kalamos/pull/114)。桌面平台人工驗收不算自動化通過；Web 改用瀏覽器與資料庫對應原生操作。

### 1. 盤點與驗證高風險功能

- [x] 建立可保留在 `web/docs/` 的桌面功能對照表 — 每項功能記錄桌面依據、Web 操作、驗收測試與狀態；涵蓋 WEB-01 至 WEB-06，以及桌面文件未盡列的分頁、搜尋、Quick Open、偏好、異常救回、原生選單和 `Open With`。以桌面原始碼及測試逐項核對，不把未實作的功能標為完成。
- [x] 驗證瀏覽器可完成的匯入方式 — 先以桌面 Chrome／Edge 作為驗收基準，試作 `.md` 選檔、明確選取附件或資料夾及保留相對路徑；以含子資料夾、同名檔案及取消選取的樣本記錄結果。Safari／Firefox 不自動列入支援承諾。
- [x] 驗證桌面專用功能的 Web 對應 — 用小型樣本確認本機 PDF 工具能產生巢狀書籤、公式和圖表；驗證 Pandoc 的受限轉檔、缺少工具時的提示，以及管理者明確啟用圖床整合的方式。記錄選用工具、自訂 CSS 與作業系統功能的對應；若無法達成等效結果，列出具體缺口，不以列印或省略功能當作通過。

### 2. 建立本機啟動方式與文件持久化（WEB-01、WEB-04）

- [x] 建立 Web 入口、本機 TypeScript API 及開發指令 — 在不依賴根目錄桌面 Vite 頁面的情況下，讓瀏覽器可呼叫同源 API，並驗證 API 能用獨立的 PostgreSQL 測試資料庫。確認服務只從本機存取，啟動失敗會指出資料庫未就緒，且前端看不到 DB 帳密。
- [x] 建立 SQL 初始遷移及文件 API — 實作文件新建、列出、讀取、儲存、改名及刪除；測試空資料庫遷移、再次執行、名稱衝突、版本衝突與資料庫錯誤。名稱或路徑不直接對應主機檔案。
- [x] 串起第一個可使用的流程 — 以最少介面完成「匯入 `.md` → 編輯 → 儲存 → 乾淨瀏覽器重開 → 下載」，保留未編輯檔案的 CRLF、UTF-8 BOM 與尾端換行狀態；測試取消與讀取失敗不改變目前文件，本機原檔內容不變。
- [x] 補上儲存狀態與資料保護 — 明確區分儲存中、已儲存與失敗；自動儲存及手動儲存不能讓較舊回應清掉較新編輯。測試兩分頁的版本衝突、DB 中斷、重試、下載未儲存內容，以及重新開啟時辨識可救回的草稿。若使用瀏覽器暫存，不把它顯示成已存入 DB。

### 3. 接上共享編輯器、附件與工作區（WEB-02 至 WEB-05）

- [x] 將 Web 入口接上共享編輯器 — 使用同一組測試文件比對單欄即時預覽與原始碼模式、粗斜體、清單、連結、註腳、Front Matter、目錄、自動配對和 Emoji。確認模式切換保留游標，並測試 GFM 表格儲存格編輯、程式碼高亮、MathJax 和桌面版支援的 Mermaid、`flow`、`sequence` 圖表。
- [x] 實作圖片匯入與解析 — 使用工作區的相對路徑配對使用者已選取的附件，不向主機查找未授權檔案。以 `assets/example.png` 驗證匯入後可預覽、重開仍可讀取，並驗證拖放、貼上、尺寸、根路徑、缺檔與同名衝突。先保存附件再更新文件引用，失敗時不留下無法使用的連結。
- [x] 完成工作區操作 — 串起樹狀導覽、列表、大綱、分頁、文件內搜尋、工作區搜尋、Quick Open、改名與刪除。用多份文件驗證每個分頁各自保留復原歷史與游標、相對文件連結可用、DB 更新後清單重整，以及刪除後可從工作區垃圾桶還原；記錄明確重新匯入如何取代桌面檔案監聽。
- [x] 接上寫作工具與偏好 — 對齊字數統計、專注模式、打字機模式、內建／自訂主題及偏好；驗證主要操作可用鍵盤、繁中組字不中斷，並且重開後設定維持；瀏覽器保留的快捷鍵要有可見的替代入口。
- [x] 接上經驗證的圖床整合 — 僅允許操作者從應用程式設定選擇及啟用整合，文件本身不得決定命令或目的地。驗證未設定提示、主動上傳後替換網址及失敗時保留原引用；不把預覽或儲存變成未告知的外部傳輸。

### 4. 完成 PDF 與多格式匯入／匯出（WEB-06）

- [x] 產生可驗收的 PDF 下載 — 使用步驟 1 驗證過的工具，在本機完成渲染；用含巢狀標題、表格、圖片、公式與圖表的文件檢查頁面與 PDF 書籤，不只確認下載有檔案。
- [x] 串接 Pandoc 匯入與匯出 — 以桌面版各方向支援的格式為清單，用實際樣本驗證標題、清單、表格、數學與附件（依格式能力）；缺少工具、格式不支援或轉檔失敗時，保留目前文件並指出原因。測試完成或失敗都清理暫存檔。

### 5. 整合本機 Compose 與測試

- [x] 把實際 Web/API 服務加入 [Compose](../../compose.yaml)，並同步更新[開發說明](../../README.md) — 保留 PostgreSQL 具名磁碟區及目前本機限制，記錄啟動、健康檢查、資料遷移、測試、備份與還原指令。使用獨立測試專案執行 `up`、匯入、`down`、再 `up`，確認乾淨瀏覽器可讀回文件與附件。
- [x] 建立 Web 專用的 Playwright 測試 — 對真實 Web/API/PostgreSQL 執行，不載入桌面 IPC 模擬；驗證 WEB-01 至 WEB-06、資料庫中斷、版本衝突及核心流程不需外網。圖床等明確啟用的外部操作用本機測試替身驗證。
- [x] 執行既有桌面建置、單元與端對端回歸測試 — 核對共享編輯器變更沒有改變桌面檔案、分頁、圖片或匯出行為；記錄命令、結果與尚未完成的平台檢查。

## Rollback / Recovery

- 所有重建、故障注入與清除資料只在獨立 Compose 專案、空白測試 DB 與測試磁碟區執行。開發者的環境停止服務只用 `down`，不加 `--volumes`。
- 在有文件的資料庫上執行不相容遷移前，停止寫入並以 `pg_dump` 備份。遷移失敗時保持停止寫入，保留現有磁碟區，將備份還原到獨立資料庫；驗證文件、附件與設定，再讓相容版本連回。不要用刪除磁碟區取代復原。
- 備份還原測試至少核對一份含附件、設定和中英混合內容的文件，包含重開、預覽與下載。

## Completion Checklist

- [x] `docker compose -f web/compose.yaml config -q` 通過；依 README 可在本機啟動完整服務、重建後讀回資料，且不需要公開網域。
- [x] Web 建置、型別檢查、單元、真實 DB 整合測試及端對端測試通過；測試紀錄對應 WEB-01 至 WEB-06。既有 `npx biome ci`、桌面版 `npm run build`、`npm test` 與 `npm run test:e2e` 通過；若共享變更觸及 Rust，依[現有 CI](../../../.github/workflows/ci.yml)執行 Rust 測試與 Clippy。
- [x] 桌面功能對照表逐項有通過證據或清楚的 Web 等效行為；公式、圖表、本機圖片、PDF 和多格式轉檔不因未選定工具而被標成首版完成。已驗證獨立資料庫的備份還原。
- [x] README 的命令經實際執行，且說明可用瀏覽器、選用工具、匯入不覆寫原檔、自管 DB 的保存／備份方式與本機存取範圍。

## External Handoff

- **目標平台操作者** — 前提：已有本機可啟動的候選版與驗收樣本。操作：在自動化環境無法取得的 macOS／Windows 或實際繁中輸入法上，核對組字、原生檔案選擇與瀏覽器保留快捷鍵。預期：主要流程可完成且組字不跳動。未驗證項目：未取得的瀏覽器／作業系統組合。限制：不對未驗證的組合宣稱支援；不因此規劃公開部署。
